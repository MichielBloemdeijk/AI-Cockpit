[M4 acceptance and reproduction](m4-acceptance.md) and [redacted JSON](m4-current.json)
record both small reference workflows, shared capability/security/lifecycle tests,

The M0 probe is implemented as:

```powershell
cd backend
uv sync --group codex-probe
uv run --group codex-probe python -m app.jarvis_tasks probe-codex `
  --report ../docs/jarvis-tasks/reports/codex-m0-current.json
```

Add `--live` only when an isolated Jarvis profile is authenticated or an
`OPENAI_API_KEY`/`CODEX_API_KEY` is explicitly available. Live mode can incur
API charges. The probe never uses the desktop Codex profile directly, does not
report credentials, and exits nonzero when required evidence fails or is
missing.

Current host result (2026-09-22): M0 passes for pinned Codex `0.155.1` on
Windows 10.0.19045 using the guarded API-authenticated route. The latest live
report contains 18 passes, no failures, and no gating blockers.

The earlier filesystem failures were invalid probe configuration: the isolated
profile did not explicitly select a Windows sandbox backend, and the SDK host
was not bound to the tested workspace. The corrected probe selects the
`unelevated` ACL sandbox, sets the host workspace, and proves read-only denial,
an allowed in-workspace write, and denial outside that workspace. `unelevated`
is the minimum verified mode on this host; production code must fail closed if
the same startup checks fail.

Windows-sandboxed `command/exec` processes do not support
`command/exec/terminate`. The chosen immediate-stop boundary is therefore one
App Server process tree per writable execution. The probe kills that tree and
confirms its descendant writer cannot modify the workspace afterward. Normal
pause/yield finishes the current bounded broker action; immediate pause and
cancel use the proven process-tree stop.

Workflow profiles disable native shell/unified exec, web search, and subagents,
and expose exactly one allowlisted Jarvis MCP fixture tool. The live probe calls
that tool and confirms its operation record is fsynced before tool success is
reported. A separate crash fixture proves completed operations are reusable and
an effect interrupted before success restores as `uncertain` with automatic
replay forbidden. Native streamed completion remains observational and is not
used as the durable checkpoint.

API-authenticated continuation passes across an App Server restart. Subscription
continuation was deliberately non-gating for that M0 API-route report because no
separate Jarvis ChatGPT profile was used. It is now a required M9 gate before M10.
Subscription stays disabled until the separately authorized profile passes and
uses one shared credential owner; desktop credentials are never reused or copied.

Reports are redacted JSON. `codex-m0-current.json` is the local inventory gate;

## Android API-37 M2 fixture

`android-m2-api37-current.json` records the 2026-09-30 passing API-37.0
Google APIs revision-6 run. Run it unattended with:

```powershell
cd backend
uv run python ../android/scripts/verify-screen-workflow.py --timeout 300
```

The harness defaults to the installed `JarvisM3Api37` AVD (4 GB RAM), tests the
actual local-network permission dialog's denial and allow-to-pair flow, and
invokes the native system assistant key. Pixels originate only in
`onHandleScreenshot`. Fake Live routes admission to a real guarded Codex worker;
the Android completion notification opens the maintained result and a force-stop
reconnect preserves one worker attempt. The script retains `report.json`, UI
hierarchies, logs and its disposable database in its printed temp directory.

The earlier API-37 package search omitted the `.0` package suffix and required
the AOSP `default` tag; the installed full phone image uses `google_apis`.
API-37 verification exposed local-network permission and assistant resource
declarations missing from the app; both were fixed. The
[local-network requirement](https://developer.android.com/privacy-and-security/local-network-permission)
and [Android-17 voice service enforcement](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android17-release/services/voiceinteraction/java/com/android/server/voiceinteraction/VoiceInteractionManagerService.java)
explain the observed failures. Capture uses the system invocation path without
disabling platform restrictions. Custom-wake screenshot integration, native
fresh/protected cases and production provider/physical timing were open at
that checkpoint; the pre-M3 reports below supersede the native feasibility gap.
